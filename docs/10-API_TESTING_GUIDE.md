# 10 - API Testing Guide (end to end)

> **Generated by `npm run docs:guide`** from a real run of the API (2026-10-25). Do not edit by hand: change the code, then re-run it. It fails if any step returns an unexpected status, so it is also a smoke test.

This guide shows the whole life of the API: sign in, manage employees, invite people, refresh tokens, deactivate, and prove that companies cannot see each other. Every step shows the request body and the real response.

## 1. Set up (5 minutes)

```bash
docker compose up -d postgres          # PostgreSQL (on a machine with a native PostgreSQL, map the port to 5433)
cd apps/api
npx prisma migrate deploy && npx prisma db seed
npm run start                          # API on http://localhost:4000/api
```

| What | Where |
|---|---|
| Interactive docs (try routes in the browser) | http://localhost:4000/api/docs |
| OpenAPI file for Apidog / Postman | http://localhost:4000/api/docs-json  or  `docs/api/openapi.json` |
| Development Admin (from the seed) | `admin@checkpoint.local` / `AdminPassword123!` |

**Test with:** Swagger UI (click **Authorize**, paste the `accessToken`), Apidog, Postman, or `curl`.

## 2. Five ideas you need

1. **Two tokens.** Login returns an `accessToken` (15 minutes, send it as `Authorization: Bearer ...`) and a `refreshToken` (30 days, single-use, exchanged at `/auth/refresh`).
2. **Roles.** `ADMIN` may call `/admin/*`. `EMPLOYEE` gets **403** there and may call `/me/*`. An account that still has a one-time password gets **403 `PASSWORD_CHANGE_REQUIRED`** everywhere until it calls `PATCH /me/password`.
3. **Company scope.** Your company is inside your token. You never send it. Another company's record answers **404**, exactly like a missing one.
4. **Errors** always look like `{ "statusCode": 404, "message": "...", "error": "Not Found" }`. A 400 lists every validation problem and rejects unknown fields.
5. **Money** is EGP, and amounts come back as strings (`"12000"`).

## 3. The cycle, step by step

The Admin trades email and password for two tokens. Use `accessToken` on every request (15 minutes). Keep `refreshToken` to get a new pair later (30 days, single-use).

{

  "password": "AdminPassword123!"
}

### Step 9. Everything else is blocked until she changes it

Only `GET /auth/me`, logout and `PATCH /me/password` work. Other routes answer **403** with the machine-readable `code: PASSWORD_CHANGE_REQUIRED`.

**Request**

```http
GET /api/me/profile
Authorization: Bearer <accessToken>
```

**Response 403**

```json
{
  "statusCode": 403,
  "message": "You must change your password first: call PATCH /api/me/password",
  "error": "Forbidden",
  "code": "PASSWORD_CHANGE_REQUIRED"
}
```

### Step 10. Change the password

The new password must differ from the current one (8+ characters). All sessions end, so she signs in again. Wrong current passwords are rate-limited.

**Request**

```http
PATCH /api/me/password
Authorization: Bearer <accessToken>
Content-Type: application/json

{
  "currentPassword": "Password123!",
  "newPassword": "BrandNew#Pass9"
}
```

**Response 200**

```json
{
  "success": true,
  "message": "Password changed. Please sign in again."
}
```

### Part D: Tokens, refresh and theft detection

### Step 21. Refresh

Returns a NEW pair. The refresh token you sent is now spent: replace both stored tokens.

**Request**

```http
POST /api/auth/refresh
Content-Type: application/json

{
  "refreshToken": "8ec40e118880cfcea4…(64 chars)"
}
```

**Response 200**

```json
{
  "accessToken": "eyJhbGciOiJIUzI1Ni…(516 chars)",
  "refreshToken": "6c1ec386afceb40809…(64 chars)"
}
```

### Step 22. Replay the spent refresh token (a stolen copy)

Reuse is treated as theft: the whole session family is revoked and this returns 401.

**Request**

```http
POST /api/auth/refresh
Content-Type: application/json

{
  "refreshToken": "8ec40e118880cfcea4…(64 chars)"
}
```

**Response 401**

```json
{
  "message": "Refresh token reuse detected. All sessions in this family revoked.",
  "error": "Unauthorized",
  "statusCode": 401
}
```

### Step 23. The legitimate newer token is dead too

Because the family was revoked, the user must sign in again. This is the intended safety behaviour.

**Request**

```http
POST /api/auth/refresh
Content-Type: application/json

{
  "refreshToken": "6c1ec386afceb40809…(64 chars)"
}
```

**Response 401**

```json
{
  "message": "Refresh token reuse detected. All sessions in this family revoked.",
  "error": "Unauthorized",
  "statusCode": 401
}
```

## 4. Every route at a glance

| Method | Path | Needs | What it does |
|---|---|---|---|
| `GET` | `/api/admin/audit-events` | Bearer token | Read the audit log of my company |
| `POST` | `/api/auth/login` | **Public** | Sign in with email and password |
| `POST` | `/api/auth/refresh` | **Public** | Exchange a refresh token for a new token pair |
| `POST` | `/api/auth/logout` | **Public** | Sign out (revoke the whole session family) |
| `GET` | `/api/auth/me` | Bearer token | Who am I? (the claims of my access token) |
| `GET` | `/api/auth/test-permission` | Bearer token | Diagnostic: succeeds only if the token has users.read |
| `POST` | `/api/admin/users` | Bearer token | Create a user and employee in my company |
| `GET` | `/api/admin/users` | Bearer token | List users of my company |
| `GET` | `/api/admin/users/{id}` | Bearer token | Get one user with salary history |
| `PATCH` | `/api/admin/users/{id}/status` | Bearer token | Activate or deactivate a user |
| `POST` | `/api/admin/users/{id}/salaries` | Bearer token | Add a salary version |
| `GET` | `/api/me/profile` | Bearer token | My own profile |
| `PATCH` | `/api/me/password` | Bearer token | Change my password |
| `POST` | `/api/admin/invitations` | Bearer token | Invite an employee into my company |
| `GET` | `/api/admin/invitations` | Bearer token | List my company's invitations |
| `DELETE` | `/api/admin/invitations/{id}` | Bearer token | Revoke a pending invitation |
| `POST` | `/api/auth/invitations/accept` | **Public** | Redeem an invitation and create my account |

## 5. Status codes you will meet

| Code | Meaning here |
|---|---|
| 200 / 201 | Done |
| 400 | Invalid body, or an invalid/used/expired invitation token |
| 401 | No/expired token, wrong credentials, deactivated account, or a refresh token that is spent |
| 403 | Signed in, but your role lacks the permission |
| 404 | Not in **your** company (or does not exist) |
| 409 | Duplicate (email, employee code, pending invitation) or wrong state |
| 429 | Too many WRONG login, invitation or password attempts (successful sign-ins never count) |

## 6. Import into Apidog (or Postman / Insomnia)

1. Start the API, or just use the file `docs/api/openapi.json`.
2. **Apidog:** *Project settings → Import data → OpenAPI/Swagger →* choose the file, **or** paste the URL `http://localhost:4000/api/docs-json` (re-import it any time to refresh).
3. Create an environment variable `baseUrl = http://localhost:4000` and a variable `accessToken`. Set the project's auth to *Bearer Token* = `{{accessToken}}`.
4. Run **POST /api/auth/login**, copy `accessToken` into the variable, then run any route.
5. The request bodies already contain working examples; the schemas list every field with its type and example.

## 7. Keeping the docs current (for developers)

- Every route needs `@ApiOperation` (with a scenario), `@ApiTags`, and response decorators. Request and response bodies are classes with `@ApiProperty`.
- After adding or changing a route run **`npm run docs:openapi`** (rewrites `docs/api/openapi.json`) and **`npm run docs:guide`** (rewrites this file).
- The unit test `src/swagger.spec.ts` **fails** if `docs/api/openapi.json` is out of date or a route has no summary, tag or response, so CI catches a forgotten update.
